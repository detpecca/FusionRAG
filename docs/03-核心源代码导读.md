# 核心源代码导读

完整可运行的 RAG 链路源代码位于仓库 `fusionrag/` 包（本文件为导读）。
运行方式见 `README.md`：`python -m fusionrag` 或 `docker compose up -d --build`。

## 1. 目录结构

```
FusionRAG/
├── fusionrag/                 # 核心源代码包
│   ├── __init__.py            # 包导出: FusionRAG / FusionRAGConfig / QueryParam
│   ├── __main__.py            # python -m fusionrag 启动入口 (uvicorn)
│   ├── config.py              # 全部可调参数 + 环境变量加载
│   ├── core.py                # 主类: ainsert(写入链路) / aquery(查询链路) / 文档删除一致性
│   ├── chunking.py            # token 滑窗切分
│   ├── extract.py             # 实体/关系抽取 + gleaning 补抽 + 结果解析
│   ├── merge.py               # 实体/关系去重合并 + 批量向量入库
│   ├── query.py               # 关键词提取、三路检索、rerank 集成、引用溯源、流式生成
│   ├── rerank.py              # rerank 精排客户端 (Jina/Cohere 风格 + 百炼 DashScope)
│   ├── prompts.py             # 全部 prompt 模板
│   ├── llm.py                 # OpenAI 兼容 LLM/Embedding 客户端 + 缓存 + 限流重试
│   ├── storage.py             # 存储抽象基类 + JSON 后端 (KV / 向量 / 图) + 后端工厂
│   ├── storage_sqlite.py      # SQLite KV 后端 (内存缓存 + 增量落盘)
│   ├── sessions.py            # 会话历史 (滑动窗口)
│   ├── api.py                 # FastAPI: 文档导入/对话/会话 + 文档列表 + 文件导入(SSE 进度)
│   └── utils.py               # tokenizer / 哈希 id / 余弦相似度 / token 截断
├── webui/index.html           # ChatGPT 风格聊天界面 (单文件, 零构建)

```

## 2. 模块职责与 RAG 链路映射

| 模块 | 职责 |
|---|---|
| `chunking.py` | token 滑窗切分（1200/100） |
| `extract.py` | 分隔符格式抽取、gleaning 补抽、解析规范化 |
| `merge.py` | 按名去重、增量合并、LLM 摘要、批量向量入库 |
| `query.py` | 高/低层关键词、local/global/naive/hybrid 检索、引用列表组装 |
| `rerank.py` | 候选 chunk 精排（低分过滤 + top_n 截断），失败自动回退 |
| `storage.py` | KV / 向量 / 图三类存储抽象与 JSON 后端，可插拔 |
| `storage_sqlite.py` | KV 的 SQLite 后端，消除 JSON 全量重写的写放大 |
| `llm.py` | LLM/embedding 封装、结果缓存、429 重试 |
| `core.py` | 两条链路的编排与状态机、文档删除一致性、embedding 指纹校验 |
| `api.py` | REST 接口与 SSE 流式 |

## 3. 写入链路（文档导入）调用顺序

`core.py: FusionRAG.ainsert` 依次调用：

1. **切分** `chunking.chunking_by_token_size`：token 滑窗 → `[{tokens, content, chunk_order_index}]`，
   以 `chunk-<md5(doc_id+序号)>` 为键；
2. **入库** KV.upsert（chunk 原文）+ 向量库.upsert（chunk 向量）；
3. **抽取** `extract.extract_entities`：每个 chunk 并发调 LLM（信号量限流），
   输出格式 `entity<|#|>名字<|#|>类型<|#|>描述` / `relation<|#|>源<|#|>目标<|#|>关键词<|#|>描述`，
   `<|COMPLETE|>` 结束；随后 1 轮 gleaning 补抽（首轮对话作历史，同名记录保留描述更长者）；
   解析时做字段规范化（类型小写取首项、全角逗号转半角、自环丢弃、超长名丢弃）；
4. **去重合并** `merge.merge_nodes_and_edges`：
   - 实体按 `entity_name` 聚合，关系按排序后 `(src,tgt)` 无向聚合（`(A,B)`=`(B,A)`）；
   - `description`：新旧精确去重后 `<SEP>` 拼接；片段数 ≥ 8 或超 1200 token 时 LLM 摘要压缩；
   - `weight`：仅对未出现的 `source_id` 累加（重复导入不重复计数）；
   - `source_id`：保序去重归并（上限 200）；`entity_type` 投票取多数；`keywords` 并集字典序连接；
   - 关系缺失端点自动补 `unknown` 占位节点；
   - 实体向量文本 `名字\n描述`、关系向量文本 `关键词\tsrc\ntgt\n描述`，**最后批量一次写入**向量库；
5. **状态落库**：`full_docs` 记 PROCESSED（含统计），全部存储原子 flush；异常置 FAILED 并留 error_msg。

全程通过 `progress_callback(stage, current, total)` 上报进度，供 API 层转 SSE 推送。

## 4. 查询链路（增强问答）调用顺序

`core.py: FusionRAG.aquery` → `query.rag_query`：

1. **关键词提取** `query.extract_keywords`：LLM 输出 JSON
   `{"high_level_keywords": [...], "low_level_keywords": [...]}`（容错解析；皆空且问题 < 50 字时整句兜底为低层关键词）；
2. **三路检索**（按 mode 组合）：
   - `local`：低层关键词向量 → 实体向量库 top_k → `graph` 批量取节点/度数 → 一跳扩展全部邻边（按 weight 排序）
     → 按实体 `source_id` 收集候选 chunk，用问题向量与候选 chunk 向量算余弦精选；
   - `global`：高层关键词向量 → 关系向量库 top_k → 扩展相连实体 → 同理选 chunk（与实体侧已选去重）；
   - `naive`：问题向量 → chunk 向量库 top_k；
3. **rerank 精排**（可选，`rerank.py`）：三路 chunk round-robin 合并后整体过 rerank 模型，
   按相关分重排 + 低分过滤 + `RERANK_TOP_N` 截断；服务不可达/报错时回退原始排序，不阻断问答；
4. **合并截断**：实体/关系 round-robin 交替合并去重；分别按 `max_entity_tokens`(6000) /
   `max_relation_tokens`(8000) 截断；chunk 按剩余动态预算
   （`max_total_tokens` − 已用 − buffer 200）截断；
5. **生成**：组装 `---Entities--- / ---Relationships--- / ---Document Chunks---` 上下文注入系统 prompt
   （要求严格基于上下文、找不到就明说不知道），携带滑动窗口历史调 LLM；
   `stream=true` 时返回异步迭代器，API 层转 SSE 逐帧下发；
6. **引用溯源**：按最终进入上下文的 chunk 生成引用列表
   `{reference_id, chunk_id, doc_id, title, score, excerpt}`，随响应一并返回（流式在 [DONE] 前补一帧）。

## 5. 关键设计取舍

- **幂等导入**：doc_id = 内容 MD5，PROCESSED 状态文档重复导入直接 SKIPPED；
- **防重跑污染**：weight 只对新 source_id 累加、描述精确去重、LLM 结果全量缓存（`kv_llm_cache`），
  同一文档重跑/多轮导入结果稳定且成本低；
- **限流友好**：LLM 并发 4、embedding 并发 8（信号量），429/5xx 指数退避重试 5 次；
- **可替换**：`FusionRAGConfig.llm_func / embedding_func / rerank_func` 可注入任意实现
  （测试用 Fake 实现即走此通道），存储接口可平替生产级后端；
- **embedding 指纹**：启动时校验 embedding 模型/维度与存量向量一致
  （`embedding_meta.json`），不一致直接拒绝启动，防换模型后向量静默损坏；
- **删除一致性**：`core.adelete_by_doc_id` 按实体/关系 chunk 账本做"真删/扣减/不动"三分支裁决，
  关系 weight 按剩余来源重算，存活实体/关系的描述用剩余 chunk 重抽（LLM 缓存命中）重建，
  删除幂等可重发（详见 `docs/01-架构设计说明.md` §6）。
