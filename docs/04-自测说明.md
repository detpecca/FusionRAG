# 自测代码与用例说明

测试分两层：**单元/API 测试**（`tests/`，74 个用例，不依赖外部 API）与
**真实端到端验证**（`scripts/e2e_real.py`，连真实 LLM/Embedding/Rerank）。

## 1. 运行方式

```bash
pip install -r requirements-dev.txt
pytest -q          # 74 passed
```

测试通过 `FusionRAGConfig.llm_func / embedding_func / rerank_func` 注入**确定性 Fake 实现**
（`tests/conftest.py`）：

- Fake LLM 按 prompt 特征分发：抽取请求返回固定的分隔符格式记录（3 实体 + 2 关系），
  gleaning 返回 1 个补抽实体，关键词请求返回固定 JSON，问答返回固定句子（流式分 3 段）；
- Fake Embedding 为词袋哈希向量（128 维）：共享词越多余弦相似度越高，使检索结果可断言；
- Fake Rerank 返回指定的 (index, score) 列表，用于验证重排/过滤/回退；
- 每个用例使用独立临时 `working_dir`（pytest `tmp_path`），互不污染。

## 3. 真实端到端验证（`scripts/e2e_real.py` / `scripts/verify_delete.py`）

连接真实模型服务（Kimi Coding API `kimi-for-coding-highspeed` + `bge_m3_embed` 1024 维向量，
rerank 走百炼 `gte-rerank-v2`），依次验证：导入真实文档 → hybrid 问答（含引用溯源与
rerank 精排分）→ 多轮对话 → naive 对照 → SSE 流式 → 会话历史 → 清理会话；
`verify_delete.py` 覆盖真实删除链路（账本裁决 + 描述重建）。运行前置：服务已启动且 `.env` 配置完成。

```bash
python -m fusionrag            # 或 docker compose up -d
python scripts/e2e_real.py
python scripts/verify_delete.py
```

最近一次真实验证结果（Docker 容器内）：

- 导入企业背景文档：3 片段，抽取 **142 实体 / 196 关系**，状态 PROCESSED；
- 上传论文片段（1.5 万字符 .txt）：2 片段，**79 实体 / 90 关系**，
  进度事件 `chunked → vectorized → extracting 2/2 → merging 169/169 → finalizing → done` 完整；
- hybrid 问答正确且接地，响应附带引用列表（文档标题 + 片段摘录 + rerank 精排分），
  rerank 后候选片段区分度显著提升（0.75 / 0.60 / 0.18 vs 粗排 0.58 / 0.55 / 0.52）；
- 删除文档后共享实体/关系的描述、source_id、weight 与向量均保持一致；
- 流式、多轮历史、会话清理均符合预期。
